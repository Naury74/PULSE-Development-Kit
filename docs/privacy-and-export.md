# 개인정보와 내보내기

## 저장 전 마스킹

- 헤더·URL·실패 메시지는 수집 큐에 넣기 전에, 본문은 저장 스레드에서 마스킹합니다. 저장소는 마스킹을 거친 기록 타입만 받습니다.
- 가린 값은 `[REDACTED]`로 바뀌고 원래 값은 어디에도 남지 않습니다. 원래 값을 보여 주는 기능은 없습니다.
- 마스킹할 수 없는 본문은 저장하지 않고 이유만 남깁니다.
- URL의 사용자 정보(`user:pass@`)와 fragment는 지웁니다. 경로 안의 비밀은 알 수 없어 그대로 둡니다.
- JSON 본문은 민감한 키의 값을 가리고, 문자열 값도 살펴봅니다. 문자열이 JSON이면 두 단계까지 풀어 같은 규칙을 적용하고, 그 밖에는 문자열 안의 URL 쿼리와 `name=value` 형태의 민감 값을 가립니다. 받은 요청을 그대로 되돌려 주는 서버의 응답에 대비한 것입니다. 이 형태가 아닌 자유 텍스트 속 비밀(예: `"비밀번호는 1234"`)은 알아낼 수 없습니다.

## 저장 위치

`noBackupFilesDir/pulse/`(Room DB `pulse.db`와 본문 파일 `bodies/`). 자동 백업·기기 이전 대상이 아닙니다. `clear()`나 설정 탭의 지우기로 모두 지울 수 있습니다.

## 화면

인스펙터 Activity는 `exported=false`입니다. debug 빌드의 런처 아이콘만 다른 앱(런처)이 열 수 있으며, 화면을 띄울 뿐 데이터를 돌려주지 않습니다. 본문 복사는 버튼을 누를 때만 하며 Android 13 이상에서는 클립보드 미리보기에 내용을 숨깁니다.

알림은 최근 요청의 메서드·경로·결과를 보여 줍니다. 잠금 화면에서는 개수만 보이고, 끄려면 `pulse_notification_enabled`를 false로 둡니다. 요청 공유는 사용자가 고른 앱에만 보내며, 마스킹했더라도 개인정보가 남을 수 있으니 공유 전에 확인하세요.

## 내보내기

트래픽 탭의 내보내기는 현재 검색·필터에 맞는 요청(최신순, 최대 10,000개)을 사용자가 고른 위치(Storage Access Framework)에만 씁니다. 자동으로 공유하거나 업로드하지 않습니다.

- **HAR 1.2**: 관찰하지 못한 타이밍은 `-1`, 전송 크기(`bodySize`, `headersSize`)는 알 수 없어 `-1`입니다. PULSE 정보는 `_pulse` 확장 필드에 있습니다.
- **PULSE JSON**(`pulse.capture.v1`): 본문 상태·마스킹 수·타이밍 단계를 모두 담습니다.
- 쓰기 직전에 현재 정책으로 **다시 마스킹**합니다. 다시 마스킹할 수 없는 본문은 빼고, 뺀 수를 알려 줍니다.
- 실패하거나 화면을 떠나 취소되면 쓰다 만 파일을 지웁니다.
- **cURL 복사**: 값이 가려진 헤더는 넣지 않고 주석으로 알리며, 상태를 바꾸는 메서드에는 경고 주석을 붙입니다.

마스킹했더라도 파일에 개인정보가 남을 수 있으니 공유하기 전에 확인하세요.
