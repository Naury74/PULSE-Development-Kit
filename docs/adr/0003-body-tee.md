# ADR-0003: 본문은 호스트 앱이 실제로 주고받는 바이트만 복사(tee)

상태: 채택

## 배경

응답 본문은 스트리밍될 수 있고 한 번만 읽을 수 있습니다. 요청 본문은 one-shot이거나 duplex일 수 있습니다. SDK가 본문을 미리 읽거나 두 번 쓰면 호스트 앱의 동작이 달라집니다.

## 결정

- 응답: 원래 `ResponseBody`를 감싼 `ForwardingSource`가 호스트 앱이 `read`한 바이트만 상한까지 복사합니다. EOF에 도달했을 때만 저장 대상으로 넘기고, 끝까지 읽기 전에 닫히면 `INCOMPLETE_READ`로 기록합니다. 미리 읽거나 버퍼에 모아 두지 않습니다.
- 요청: JSON이면서 one-shot이나 duplex가 아닐 때만 `RequestBody`를 감싸고, OkHttp가 네트워크로 쓰는 바이트를 복사합니다. 본문을 따로 한 번 더 쓰지 않습니다. 리다이렉트나 재시도로 여러 번 쓰이더라도 처음 끝까지 쓴 결과만 사용합니다.
- 상한을 넘으면 복사본을 버리고 바이트 수만 셉니다.
- HEAD, 1xx, 204, 304 응답과 길이가 0인 응답은 본문을 기다리지 않고 바로 완료로 기록합니다.

## 결과

- 호스트 앱이 본문을 읽지 않으면 본문은 기록되지 않습니다.
- 감싼 요청 본문 객체가 호스트 앱의 인터셉터에도 보이므로, JSON 본문에만 적용해 `FormBody`, `MultipartBody` 타입 검사가 깨지지 않게 합니다.
